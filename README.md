# Ускорь индексацию

Подборка доступных товаров по рекомендациям с учётом исключений и повторений.

## Начало работы

Реализация выполнена в стартовом Kotlin-проекте. Для запуска всех тестов:

```bash
./gradlew test
```

Перед сдачей рекомендуется выполнить полную проверку:

```bash
./gradlew clean build
```

## Основное задание

### Решение

**Файл с реализацией:** `src/main/kotlin/lab2/ProductSelection.kt`

**Как работает функция и почему выбран такой способ обработки данных?**

Сначала функция создаёт Map, в которой товары хранятся по своим ID, и Set с исключениями. Это позволяет быстро находить товары и проверять, можно ли их добавить в результат.

После этого функция проходит по списку рекомендаций и добавляет подходящие товары в результат. Такой подход позволяет не перебирать весь каталог для каждого рекомендованного ID.

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Рекомендации обрабатываются по порядку исходного списка. Для проверки повторений используется отдельный HashSet с ID уже добавленных товаров.

Исключённые ID пропускаются сразу. Если товара нет в каталоге или он недоступен, он также не попадает в результат. В итоге каждый подходящий товар добавляется только один раз.

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях;
- `u` — число товаров в результате.

**Время выполнения:**

Ожидаемое `O(p + r + e)`.

Создание Map занимает `O(p)`, создание множества исключений — `O(e)`, обработка рекомендаций — `O(r)`. Проверки в хеш-коллекциях в среднем выполняются за `O(1)`.

Оценка предполагает обычную работу хеш-таблиц.

**Дополнительная память:**

`O(p + e + u)`.

Map занимает `O(p)`, множество исключений — `O(e)`, а множество уже добавленных товаров — `O(u)`. Список результата также занимает `O(u)` памяти.

## Необязательное продолжение

### Организация решения

**Файлы с реализацией и пример вызова:**

- `src/main/kotlin/lab2/ProductCatalog.kt`
- `src/test/kotlin/lab2/ProductCatalogTest.kt`

Пример использования:

```kotlin
val catalog = ProductCatalog(products)

val result = catalog.select(
    recommendedIds = listOf(3, 2, 3, 1, 4),
    excludedIds = listOf(1),
    limit = 2
)
```

**Что выполняется при загрузке каталога, а что — при каждом запросе? Как обеспечиваются независимость запросов и переход на новый каталог?**

При создании `ProductCatalog` каталог один раз преобразуется в Map для быстрого поиска товаров.

При каждом запросе отдельно создаются множества исключений и уже выбранных товаров. Результат также формируется заново, поэтому запросы не влияют друг на друга.

Если каталог обновился, создаётся новый экземпляр `ProductCatalog` с новыми данными.

**Когда прекращается просмотр рекомендаций? От чего зависит число просмотренных элементов?**

Обработка прекращается сразу после того, как количество найденных товаров достигает `limit`.

Если подходящих товаров мало или их нет, функция продолжает просмотр до конца списка рекомендаций. Поэтому количество просмотренных элементов зависит от расположения подходящих товаров и заданного лимита.

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `e` — число исключений в запросе;
- `r` — число рекомендаций;
- `v` — фактически просмотренное число рекомендаций;
- `u` — число товаров в результате.

| Этап | Время | Дополнительная память |
| --- | --- | --- |
| Подготовка каталога | `O(p)` | `O(p)` |
| Один запрос | `O(e + v)` | `O(e + u)` |

**Обоснование оценок и память для результата:**

При создании каталога Map строится один раз за `O(p)` времени и занимает `O(p)` памяти.

Для каждого запроса создаётся множество исключений за `O(e)`, после чего обрабатывается не больше `r` рекомендаций. Поиск товаров и проверки в HashSet в среднем занимают `O(1)`, поэтому время одного запроса составляет `O(e + v)`.

Дополнительная память одного запроса — `O(e + u)` для множеств. Сам список результата отдельно занимает `O(u)` памяти.

### Проверка продолжения

| Что проверяется | Тесты |
| --- | --- |
| Нулевой лимит | `zeroLimitReturnsEmptyList` |
| Досрочное заполнение результата | `stopsAsSoonAsLimitIsReached` |
| Подходящих товаров меньше лимита | `returnsAllMatchesWhenThereAreFewerThanLimit` |
| Несколько независимых запросов к одному каталогу | `requestsToSameCatalogDoNotShareRequestState` |
| Переход на новый каталог | `newCatalogInstanceUsesNewCatalogData` |

**Как подтверждено досрочное завершение?**

В тесте `stopsAsSoonAsLimitIsReached` используется каталог с двумя доступными товарами и список из пяти рекомендаций.

Установлен `limit = 1`. Первый рекомендованный товар доступен, поэтому результат заполняется сразу.

Для подсчёта просмотренных рекомендаций используется специальный callback, который увеличивает счётчик при обработке каждого ID.

После выполнения проверяется, что результат содержит один товар, а счётчик просмотренных рекомендаций равен `1`, хотя всего в списке было пять элементов.

Таким образом, тест подтверждает, что оставшиеся рекомендации не обрабатываются.
